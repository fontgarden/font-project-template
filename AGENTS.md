# Agent guidance

Font Garden Template is an OFL font project in the Font.Garden layout,
intended for Google Fonts. The release target is every glyph green in every
master. The designer draws and approves. Agents draft named glyphs, build,
proof, measure and report.

## Tools

The tools are in
[fontgarden-tools](https://github.com/fontgarden/fontgarden-tools), a shared
package that `make setup` installs with its command `fgtools`. Run them with
`make` or `.venv/bin/fgtools <command>`. Change a general tool there, not
here. Add a scripts folder only for a tool that only this font needs.

The fonts are built with fontc, the Rust compiler of Google Fonts. Build
regressions are found with diffenator3 (`make diff`). QA is Fontspector with
the Font.Garden profile (`make qa`).

## Guide

The guide of the Font.Garden system is at https://font.garden/docs. Its
source is https://github.com/fontgarden/fontgarden.github.io
(`src/content/docs/`). When you change a command, a `make` target, a mark
color, the layout or a workflow here, update the chapter of the guide in the
same session. The README of that repository lists the chapter for each kind
of change, and its script `check_guide.py` finds the differences.

## State

- Progress: [STATUS.md](STATUS.md), generated by `make status` from mark colors.
  Take direction from the designer, not from older reports in the Git history.
- Active inputs: the UFOs in `sources/` and `sources/config.yaml`. The
  design rules and the values that the tools check (grid, stroke targets,
  mark colors, QA exclusions): [context.md](context.md). It is the one design
  file: do not state a design value in another file.

## Work loop

The full description is in
[documentation/design/learning.md](documentation/design/learning.md).

1. `make queue` ranks the glyphs that most composites wait on. The designer
   names the glyphs to work on.
2. Draft, then run `make check-design GLYPHS="..."` and correct the findings.
   The checks are a filter. They do not measure quality.
3. Run `make diff`. It builds main and the working tree and compares them
   with diffenator3. Every changed glyph, word, table or language result must
   be one that the edit explains. Report the others before review.
4. Render the same text in this font and the fonts in `reference-fonts/` at
   one em size and weight. Use Runebender or `make proof-web`.
5. The designer reviews and corrects. Commit the draft before the correction,
   so that the Git history holds both. The review commit changes the purple
   mark to a grade: red (broken), orange (better), yellow (close) or green.
6. When the designer asks, run `make corrections` and propose a change for
   each open correction: a rule entry, a check, a held-out case or a glyph
   record. The change cites the correction commit. Do not add worklogs,
   reports, receipts or handoff files.

## Long and unattended tasks

Task contracts are in `.agents/tasks/`: goal, acceptance, constraints and the
report. Run a contract in a separate checkout, on its own branch. After any
agent edits glyphs, run `make check-changes`. It fails when a green glyph
changed, or when the contours of a glyph changed and it is not purple.

## What belongs in the repository

The repository holds sources, tests and maintained documents. It does not
hold records of work.

- Do not add worklogs, handoffs, receipts, reports, plans, audits or dated
  documents. The Git history and commit messages are the record of work.
- Generated output goes to `out/`, which Git ignores. A tracked file has at
  most 500 KB, because a file stays in every clone of the history. A specimen
  scan in `sources/specimen/` can be larger.
- Before you add a document, extend the existing one on the same subject.
- `tests/test_repository_layout.py` enforces these rules in CI. To add a new
  kind of file, change its LAYOUT or OPTIONAL list in the same commit and give
  the reason in the commit message.
- `tests/test_documentation_references.py` fails when a document links to a
  file, path or `make` target that does not exist. When you remove a file or
  a command, update the documents that name it in the same commit.

## Source rules

- Draw or redraw only glyphs the designer names, in the masters the designer
  names.
- A request to clean up a glyph, or to make it "more X", is the smallest
  change to the current drawing, usually handle edits. It is not a new design.
- The reference fonts do not dictate the design. Use them to compare visual
  weight, spacing and outline consistency.
- Green contour glyphs are frozen. The designer approves contour glyphs. Mark
  new AI drawing and new traces purple.
- A change to a component donor also changes every glyph that uses it. Do not
  change a donor that a green glyph uses.
- A composite that `fgtools check-design --ready` lists can be marked green.
- Keep contour, point and component structure compatible in every master.
- The em is 1024 units. Every point is on the 2-unit grid; structural points
  are on the 8-unit grid.
- Trace only from raster images. Do not copy outlines from a digital font
  file, and do not give a traced font the name of the original typeface.
- Edit GLIF XML and plists surgically in the existing style (tabs, double
  quotes, no space before `/>`). Never call whole-UFO `font.save()`.
- Register new glyphs in `contents.plist` and `public.glyphOrder` in every
  master.
- Files that people edit use TOML with comments. JSON is only for data that
  a program writes. `sources/config.yaml` is YAML because gftools requires it.

## Verification

Build with `make build`, check with `make qa` and
[documentation/qa.md](documentation/qa.md), and look at the rendered output.
Command success is not visual review. Release scope and the official Google
Fonts links are in [documentation/google-fonts.md](documentation/google-fonts.md).
Commit messages are plain, with no agent credit or trailers.
